实验 · EXPERIMENT

让 Agent 自己跑完一次代码评审

记录提示词、工具调用与失败样本，用真实数据而不是感觉评估效果。

把评审过程变成可观察的实验

一次 Agent 代码评审不应只留下“通过”或“拒绝”的结论。我们需要保留它接收了哪些上下文、调用了哪些工具，以及每一步为何改变了判断。

实验记录什么

  • 提示词：任务说明、代码范围和评审标准是否足够明确。
  • 工具调用：Agent 是否查看 diff、运行测试并追溯相关实现。
  • 失败样本：遗漏、误报和无法判断的案例，都是下一轮改进的输入。

评估的重点

评估不只看发现了多少问题，还要看问题是否真实、理由能否复核，以及流程能否稳定地重复。只有把失败也记录下来，团队才能知道该改提示词、补工具，还是调整验证环境。
